# 跨境电商运营助手项目_OPRD

[![Author](https://img.shields.io/badge/Author-🌲⛰️🐘-white.svg)](Author)    	[![Version](https://img.shields.io/badge/Version-0.2-white.svg)](Version) 

#### 【项目背景】

- **项目概述：**

  > 跨境电商运营人员日常面临大量重复性工作：查询销售数据、制作趋势报表、撰写产品Listing等。这些任务耗时费力，且需要频繁切换不同工具。
  >
  > 本项目利用 **LangChain**+**LangGraph** 框架构建一个智能运营助手，通过自然语言交互方式，让运营人员能够用"说话"的方式完成数据查询、Listing 生成、质量评估等任务，释放人力投入核心业务（选品、决策）。

- **目标用户：**

  > | 用户角色   | 典型场景                           | 解决痛点                           |
  > | ---------- | ---------------------------------- | ---------------------------------- |
  > | 初级运营   | 快速查询昨日销售冠军、生成趋势图表 | 手动处理数据耗时，难以快速获得洞察 |
  > | 内容专员   | 基于产品图片自动生成完整 Listing   | 文案构思费时，缺乏多风格比选       |
  > | 产品开发   | 初步评估产品Listing质量            | 缺乏客观标准，主观判断易出错       |
  > | 团队管理者 | 查看月度销售趋势，辅助决策         | 海量数据无法直观决策，预测能力弱   |

- **核心痛点：**

  > | 编号 | 痛点描述                                                  |
  > | :--- | :-------------------------------------------------------- |
  > | P1   | 日常数据查询和报表制作占用运营人员 **40%** 工作时间       |
  > | P2   | Listing 撰写依赖人工，平均每条耗时 **2 小时**，且风格单一 |
  > | P3   | 缺乏对 Listing 质量的量化评估，上新后才发现转化率低       |
  > | P4   | 历史销售数据无法有效利用，决策缺乏数据支撑                |

- **预期收益：**

  > | 指标                         | 目标值                                       | 衡量方式            |
  > | :--------------------------- | :------------------------------------------- | :------------------ |
  > | 数据查询任务耗时             | ≤ 10 秒（简单查询），≤ 30 秒（复杂分析）     | 系统埋点            |
  > | Listing 生成效率             | 从 2 小时缩短至 **5 分钟**（含人工微调）     | 用户反馈 + 系统记录 |
  > | 质量评估准确率（与人工一致） | ≥ 80%（评分与有经验的运营人员偏差在±10分内） | 定期抽样对比        |
  > | 生成图片成本控制             | 单图生成成本 ≤ $0.05（含备选模型）           | 云费用监控          |

#### 【产品范围与功能优先级】

**能力域划分：**

- **数据服务**：文件上传解析、自然语言查询、可视化生成、历史趋势分析
- **内容生成**：Listing 文本生成（多风格）、A+图合成
- **质量评估**：单条/批量 Listing 评分、竞品对比
- **系统管理**：权限控制、日志审计、导出、敏感词过滤

**优先级清单：**

| 优先级 | 序号 | 功能                              | 说明                                                         | 能力域   |
| ------ | ---- | --------------------------------- | ------------------------------------------------------------ | -------- |
| Must   | M-01 | 数据文件上传与解析                | 支持 CSV/XLSX 上传，自动识别字段（日期、SKU、销量等）        | 数据服务 |
| Must   | M-02 | 自然语言数据查询与可视化          | 用户输入如“展示上周每日销售额趋势”，系统返回图表+结论，响应≤30秒 | 数据服务 |
| Must   | M-03 | Listing 文本生成（多风格）        | 基于产品图+关键词，生成 3 个不同风格（专业/促销/场景）的完整 Listing | 内容生成 |
| Must   | M-04 | Listing 质量评估（单条）          | 对给定 Listing 给出评分（标题、五点、描述、关键词、图片综合），附建议 | 质量评估 |
| Should | S-01 | 产品图多角度/场景生成             | 基于 1 张主图生成 3 角度×4 场景 = 12 张图（异步处理）        | 内容生成 |
| Should | S-02 | A+ 图合成（图文叠加）             | 将 Listing 文本与产品图合成为符合亚马逊规范的 A+ 宣传图      | 内容生成 |
| Should | S-03 | 历史数据趋势分析与预测            | 基于 10 万+条历史记录，支持“Q1增长率”“下月畅销预测”等，返回报告+图表 | 数据服务 |
| Should | S-04 | 竞品 Listing 对比评估             | 输入多条竞品，输出横向对比表，标出我方优劣势                 | 质量评估 |
| Should | S-05 | 结果人工校审与一键重试            | 对生成内容（文本/图片）提供“认可”“修改意见”“重新生成”按钮    | 系统管理 |
| Should | S-06 | 敏感词与合规过滤                  | 自动检测生成的 Listing 是否含禁用词/虚假宣传，并高亮提示     | 系统管理 |
| Could  | C-01 | 多格式导出（Excel/PDF/Word）      | 支持查询结果、评估报告、Listing 导出为通用格式，保留格式     | 系统管理 |
| Could  | C-02 | 批量评估（多条 Listing 同时打分） | 上传多列表格，批量输出评分报告                               | 质量评估 |
| Won't  | W-01 | 不提供图片原始设计稿编辑          | 生成的图片为成品，不提供PSD等源文件                          | -        |

#### 【用户故事 与核心流程】

**用户故事**

| 角色       | 故事                                                         | 对应 AC |
| :--------- | :----------------------------------------------------------- | :------ |
| 初级运营   | 上传本周销售 CSV，问“每日订单量趋势”，系统立即出图，快速掌握变化 | AC-01   |
| 初级运营   | 问“库存低于50的SKU”，系统列出清单，以便及时补货              | AC-02   |
| 内容专员   | 上传产品图，要求生成3种风格的Listing，系统输出完整文案供选择 | AC-03   |
| 内容专员   | 要求生成 A+ 图，系统合成图文并茂的宣传图                     | AC-05   |
| 产品开发   | 提交一条 Listing，系统打分并给出改进建议，帮助优化           | AC-06   |
| 团队管理者 | 问“Q1各品类增长率”，系统返回分析报告，辅助制定Q2策略         | AC-08   |
| 所有用户   | 对生成结果不满意，点击“重新生成”获得新版本                   | AC-11   |

**主流程图**

```
用户输入 → 意图识别 → 路由到对应Agent
  ↓
【数据查询】→ 解析文件/DB → 执行计算/聚合 → 生成图表+文字 → 返回预览
【文本生成】→ 调用多模态LLM识别图片 → 生成3个风格 → 合规检查 → 展示
【图片生成】→ 异步队列 → 生成多张图 → 存储并通知 → 展示缩略图
【质量评估】→ 抽取特征 → 对比评分模型 → 输出分数+建议 → 支持导出
【校审】→ 用户确认或修改 → 触发重试/调整
```

**异常分支**

| 异常场景                        | 系统行为                                                     |
| :------------------------------ | :----------------------------------------------------------- |
| 数据文件格式不支持或解析失败    | 提示“文件格式不支持，请上传 .csv 或 .xlsx，并确保包含日期、销量等列” |
| 查询条件模糊（如缺时间范围）    | 引导“请明确时间范围，例如‘上周’、‘2026-07-01至2026-07-07’”   |
| 图片生成超时（>60秒）           | 任务挂起，提示“生成时间较长，我们将通过消息通知您，您可稍后查看” |
| 生成内容含敏感词                | 自动高亮并建议修改，阻止直接发布，需人工确认后放行           |
| LLM 返回内容格式错误或为空      | 自动重试 2 次，仍失败则返回友好错误“生成失败，请稍后重试，或检查输入描述” |
| 数据库查询数据量过大（>50万条） | 限制查询范围，提示“数据量过大，建议缩小日期范围或筛选条件”   |

#### 【验收标准（AC）】

| 验收编号 | 关联功能 | 验收描述                                                     |
| -------- | -------- | ------------------------------------------------------------ |
| AC-01    | M-02     | 上传含日销售额的 CSV，输入“展示上周每日销售额趋势图”，系统 30 秒内返回折线图及简要分析（含上升/下降点） |
| AC-02    | M-02     | 输入“查询库存低于50的SKU”，准确列出所有符合条件的 SKU 及库存数量（支持模糊查询） |
| AC-03    | M-03     | 给定一张产品主图及关键词“环保”，生成 3 个风格不同的 Listing（专业、促销、场景），每条含标题、五点、描述、搜索词，且至少两次出现“环保” |
| AC-04    | M-03     | 生成的 Listing 通过敏感词过滤，无违规词语，若触发则自动标注并提示修改 |
| AC-05    | S-02     | 基于已生成的 Listing 文本和产品图，合成 A+ 图（尺寸符合 1200×300/300×300），文字清晰，排版美观 |
| AC-06    | M-04     | 提交一个完整 Listing（含标题、五点、描述、关键词、图片URL），系统输出评分（满分100）、各维度得分（如标题25分、描述20分等），并提供不少于 3 条改进建议 |
| AC-07    | S-04     | 上传 3 条竞品 Listing，系统生成横向对比表格，标出我方在各维度的优劣，并给出整体对比结论 |
| AC-08    | S-03     | 给定一季度销售数据库（含日期、SKU、销量、广告费），输入“分析Q1各品类季度增长率及广告ROI”，系统返回包含图表和文字的分析报告 |
| AC-09    | S-03     | 输入“预测下个月畅销品类”，系统基于历史数据给出 Top 5 预测品类及置信度（需标注历史拟合误差） |
| AC-10    | S-01     | 给定一张产品主图及要求“3个角度（正面/侧面/俯视）、4个场景（户外/室内/使用中/陈列）”，系统生成 12 张图片（异步），任务完成后通过消息通知，图片清晰无水印 |
| AC-11    | S-05     | 对任意生成的文本或图片，用户点击“重新生成”，系统重新请求并替换当前结果，保留历史版本（至少保留 3 个版本） |
| AC-12    | C-01     | 点击“导出”按钮，弹出格式选择（Excel/PDF），导出内容与预览一致（图表、表格、文本均保留） |
| AC-13    | 异常     | 当用户输入“帮我看看数据”等模糊语句，系统提示“请明确具体操作，如‘查询上个月总销售额’或‘生成趋势图’” |

#### 【非功能需求】

- 性能：

  | 指标           | 目标值                                                       |
  | :------------- | :----------------------------------------------------------- |
  | 数据查询响应   | 简单统计 ≤ 10 秒，复杂分析 ≤ 30 秒（P95）                    |
  | 文本生成响应   | 含图片识别 ≤ 15 秒                                           |
  | 图片生成任务   | 异步处理，平均每张图 ≤ 60 秒，12 张图 ≤ 10 分钟（排队时间另计） |
  | 文件上传限制   | 单文件 ≤ 50 MB，支持 CSV/XLSX/PNG/JPG                        |
  | 数据库查询容量 | 支持 100 万条记录快速检索（索引优化）                        |

- 安全

  > - **合规检查**：内置敏感词库（基于平台政策），生成内容自动扫描，违规内容阻止发布并提示。
  >
  > - **审计日志**：记录所有上传、查询、生成、导出操作，保留 180 天，支持溯源。

- 兼容性：

  > - 浏览器：支持 Chrome 90+、Firefox 88+、Safari 14+、Edge 90+ 等现代浏览器。
  >
  > - 操作系统：Web 应用；图片生成依赖 GPU 算力（云端）。

- 可维护性

  > - 基于 LangChain + LangGraph，模块解耦（数据、文本、图像各自独立）
  >
  > - 监控维度：API 调用成功率、各功能响应延迟、图片生成队列长度、LLM token 消耗

#### 【风险与依赖】

| 风险类别     | 风险描述                                       | 应对措施                                                     |
| :----------- | :--------------------------------------------- | :----------------------------------------------------------- |
| **外部依赖** | LLM API 不稳定或费用超预期                     | ① 接入两家大模型供应商（如通义千问+智谱）自动切换；<br />② 设置 token 预警阈值 |
| **外部依赖** | 图片生成服务（Stable Diffusion）输出质量不稳定 | ① 预设多套提示词模板，自动优化；<br />② 引入简单质量检测（清晰度、分辨率）；<br />③ 提供重试机制 |
| **技术风险** | 大模型“幻觉”导致数据错误或内容虚假             | ① 所有数据查询结果附上“数据来源”和计算逻辑；<br />② 生成文本增加“人工确认”步骤；<br />③ 评估报告仅作为参考，不替代人工决策 |
| **技术风险** | 图片生成耗时过长，用户等待体验差               | ① 采用异步队列+WebSocket 推送进度；<br />② 支持“通知我”功能，用户可离开页面后回来查看 |
| **法务合规** | Listing 含侵权词或虚假宣传，导致平台处罚       | ① 内置动态敏感词库（对接平台政策更新）；<br />② 强制人工确认后方可发布；<br />③ 提供“合规检查”按钮单独扫描 |
| **数据安全** | 销售数据泄露风险                               | ① 数据上传后仅临时存储于数据库，用户可随时删除；<br />② 敏感字段（如成本价）加密存储；<br />③ 所有导出文件加水印 |
| **业务风险** | 运营人员习惯手动操作，对新工具接受度低         | ① 提供详细操作视频和模板提示；<br />② 初期免费试用，展示效率对比数据；<br />③ 设立反馈通道快速迭代 |

#### 【附录：术语表】

| 术语         | 解释                                                         |
| :----------- | :----------------------------------------------------------- |
| Listing      | 电商平台产品详情页，包含标题、五点描述、产品描述、关键词、图片、A+等 |
| A+ 图        | Amazon A+ Content，图文结合的详情描述，提升转化率            |

| 意图识别     | 识别用户自然语言输入的意图，路由到对应的 Agent               |
| 异步任务队列 | 使用 Celery + Redis 管理耗时任务（如图片生成），避免阻塞     |
